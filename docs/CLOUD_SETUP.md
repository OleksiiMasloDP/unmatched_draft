# Акаунти та синхронізація між пристроями (Supabase)

Що це дає: реєстрація/вхід (пошта + пароль, Google), а драфт, власні формати та
збережені колоди автоматично з'являються на всіх пристроях користувача.
Без налаштування сайт працює як раніше (гостьовий режим), кнопки входу не показуються.

## 1. Створити проєкт
1. https://supabase.com -> **New project** (регіон ближче до гравців, наприклад Frankfurt).
2. Дочекайтесь створення (1-2 хвилини).

## 2. Створити таблицю
**SQL Editor -> New query**, вставте вміст файлу `supabase/schema.sql`, натисніть **Run**.
Скрипт створює таблицю `user_docs`, правила доступу (кожен бачить лише свої рядки),
серверний час змін і підключає Realtime.

## 3. Адреси сайту
**Authentication -> URL Configuration**
- **Site URL**: `https://oleksiimaslodp.github.io/unmatched_draft/`
- **Redirect URLs** (додайте обидві):
  - `https://oleksiimaslodp.github.io/unmatched_draft/**`
  - `http://localhost:5173/unmatched_draft/**`

Без цього посилання з листів і вхід через Google не повернуть користувача на сайт.

## 4. Способи входу
**Authentication -> Providers**
- **Email**: увімкнено. Рекомендую залишити **Confirm email** увімкненим.
- **Google** (за бажанням):
  1. https://console.cloud.google.com -> APIs & Services -> Credentials ->
     **Create credentials -> OAuth client ID -> Web application**.
  2. **Authorized redirect URI**: `https://<ВАШ-PROJECT-ID>.supabase.co/auth/v1/callback`
     (точна адреса показана на сторінці провайдера Google в Supabase).
  3. Скопіюйте **Client ID** і **Client secret** у Supabase (Providers -> Google) і увімкніть.

## 5. Ключі для сайту
**Project Settings -> API**: скопіюйте **Project URL** та **anon public** ключ.
Створіть файл `.env.local` у корені проєкту (він у `.gitignore`):

```
VITE_SUPABASE_URL=https://ВАШ-PROJECT-ID.supabase.co
VITE_SUPABASE_ANON_KEY=ВАШ-ANON-PUBLIC-КЛЮЧ
```

`anon` ключ публічний за задумом: дані захищає Row Level Security з `schema.sql`.
**Ніколи** не кладіть у фронтенд ключ `service_role`.

## 6. Запуск
```
npm install
npm run dev        # перевірка локально
npm run deploy     # збірка і публікація (ключі беруться з .env.local)
```

## 7. Перед реальними користувачами
- Стандартна пошта Supabase для листів (підтвердження, скидання пароля) має жорсткі
  ліміти й призначена для тестів. Підключіть власний SMTP:
  **Project Settings -> Authentication -> SMTP Settings** (Resend, Brevo, Mailgun тощо).
  Актуальні ліміти й тарифи дивіться на сайті Supabase.
- За бажанням змініть тексти листів: **Authentication -> Email Templates**.

## Як працює синхронізація
- Дані лишаються і в браузері (`localStorage`), і в хмарі. Зміна -> через ~1.5 с
  зберігається в хмарі, інші відкриті пристрої отримують її одразу.
- Синхронізуються: поточний драфт, власні формати, збережені колоди, забіг рогаліка та його історія.
  Мова інтерфейсу залишається налаштуванням пристрою.
- Конфлікт (змінили на двох пристроях офлайн): перемагає остання зміна.
- Перший вхід на пристрої, де вже є гостьові формати/колоди: вони зливаються з
  тими, що в акаунті. Гостьовий драфт замінюється драфтом з акаунта.
- Вихід з акаунта прибирає з цього пристрою дані акаунта (безпечно на спільному ПК);
  у хмарі вони лишаються. Гість, який ніколи не входив, свої дані не втрачає.

## Швидка перевірка
1. Зареєструйтесь на ПК, почніть драфт (кілька банів/пиків).
2. Відкрийте сайт на телефоні, увійдіть: драфт на тому ж кроці.
3. Змініть щось на телефоні: на ПК зміна з'явиться за кілька секунд.
4. Створіть власний формат на одному пристрої: він з'являється на іншому.
